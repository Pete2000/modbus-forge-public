# Modbus Forge 现场使用指南

Modbus Forge 是在 Windows 本机运行的 Modbus 调试工作台：可作为 Modbus TCP 客户端连接服务器，也可作为 TCP 服务器供外部客户端联调；RTU 对应主站与从站。它提供各角色的十六进制收发记录、轮询监视、受控写入和可编辑数据区。

术语按协议区分：TCP 使用“客户端/服务器”，RTU 使用“主站/从站”。界面名称、每条日志及导出的角色显示名均按实际传输类型区分；Unit ID 单独填写，不能用它代替 IP 或端口。连接期间通道参数锁定，断开后再修改。

> 安全提示：先使用读取功能确认设备地址、通信参数和寄存器含义。写入可能改变设备状态；只对已获授权且已确认范围的目标执行写入。

## 安装与首次启动

生成 Windows x64 安装程序：

```text
release\Modbus Forge Setup <version>.exe
```

在项目目录运行 `npm run package:win` 后生成该文件。每次打包后的文件哈希不同；部署前请从受控渠道取得本次构建的 SHA-256，并在目标机器核验。当前安装包未进行代码签名。

在受控 Windows 环境中，双击安装程序并选择安装位置。首次启动后，默认显示 TCP 配置；所有连接、读取和写入均由用户在应用内明确发起。

## 连接 Modbus TCP 设备

1. 进入 **TCP 客户端调试**，选择 **TCP 客户端**。
2. 填写目标设备的 IP/主机名、端口和超时。Modbus TCP 常用端口是 `502`，但以设备实际配置为准。
3. 点击 **连接**。状态显示“已连接”后才可发送请求。
4. 填写 Unit ID、功能码、零基起始地址和读取数量。
5. 点击 **发送读取**，在“响应解码”和“会话日志”查看结果。

若设备采用文档中的 40001/30001 一类“人类可读地址”，先确认文档的偏移规则，再填入零基地址。工具不会自动猜测或转换厂商地址表示法。

## 连接 Modbus RTU 设备

1. 将已授权的 USB-RS485/RS232 转换器接入 Windows。
2. 选择 **RTU 主站**，点击 **刷新**，从列表选择实际 COM 口。
3. 按设备参数填写波特率、数据位、校验位、停止位和超时。
4. 点击 **连接** 后发送读取请求。

RTU 通讯依赖现场接线、终端电阻、总线偏置、站号和串口参数。工具会校验 CRC 并将超时、站号错配和 CRC 错误记录到日志，但不会替代现场电气检查。

## 运行 TCP 服务器或 RTU 从站

1. 切换到 **TCP 服务器模拟** 或 **RTU 从站模拟**，选择对应的 **TCP 服务器** 或 **RTU 从站**。两者可以同时运行。
2. TCP 默认监听 `127.0.0.1:5020`，适合本机联调；若改为局域网地址，先确认网络隔离与授权。RTU 从站必须选择一个未被主站或其他程序占用的 COM 口。
3. 点击 **开始监听**。状态显示“监听中”后，外部 TCP 客户端或 RTU 主站即可访问该 Unit ID 的数据区。
4. 在对应的 **TCP 服务器数据区** 或 **RTU 从站数据区** 选择 Unit ID、数据区、零基起始地址与数量，直接编辑数值或线圈状态。

本机数据区按 Unit ID 独立保存：线圈对应 `01/05/0F`，离散输入对应 `02`，保持寄存器对应 `03/06/10`，输入寄存器对应 `04`。来自外部 TCP 客户端或 RTU 主站的写入会立即修改线圈或保持寄存器并显示在数据区；离散输入和输入寄存器只能在模拟台中编辑。

## 读取、解码与监视

首版支持以下功能码：

| 用途 | 功能码 |
| --- | --- |
| 读线圈 / 离散输入 | `01` / `02` |
| 读保持 / 输入寄存器 | `03` / `04` |
| 写单线圈 / 单寄存器 | `05` / `06` |
| 写多个线圈 / 多个寄存器 | `0F` / `10` |

读取保持或输入寄存器后，可在“响应解码”选择 16 位、32 位、IEEE 754 浮点、ASCII，以及字交换方式。原始十六进制报文始终保留，用于和设备手册或抓包结果交叉核对。

对需要持续观察的读取请求，点击 **加入轮询**，设置名称和 250–60,000 ms 的轮询间隔。监视项仅允许读取功能码；同一连接的请求由应用串行排队，避免 RTU 报文交错。

## 安全写入

持续写入与双角色验证使用独立的运行确认，操作见[双角色连续读写验证](双角色连续读写验证.md)。本节说明原有单次写入。

写入采用两步确认：

1. 填写功能码、Unit ID、零基地址和值，点击 **准备写入**。
2. 核对弹窗中的设备目标、地址和值；只有点击 **确认并发送** 才会发送报文。

确认令牌一次有效、60 秒后失效。点击 **取消，不发送** 不会产生写入报文，取消活动请求会立即关闭连接，防止迟到的 RTU 响应被错误关联到新请求。

## 导出与排障

- **保存工作区**：本机保存当前请求连接参数、请求草稿、监视项、监听配置和非零本机数据。
- **导入/导出工作区**：用于在受控环境间迁移配置与本机数据；导入不会自动启动监听或连接，先核对目标后再操作。
- **导出日志**：导出TCP 客户端/服务器与 RTU 主站/从站时间线、请求、响应、异常与取消记录。日志不包含密码字段。

| 现象 | 优先检查 |
| --- | --- |
| TCP 连接超时 | IP、端口、网络可达性、设备是否启用 Modbus TCP、超时设置 |
| RTU 超时 | COM 口占用、A/B 接线、站号、波特率/校验位/停止位、总线终端与偏置 |
| `CRC_MISMATCH` | 串口参数、线路干扰、RS485 极性与接地 |
| `RESPONSE_MISMATCH` | 设备网关路由、并发外部请求端、错误 Unit ID 或异常设备响应 |
| Modbus 异常码 | 功能码、地址偏移、寄存器是否允许当前操作、设备手册规定的数量范围 |

## 已验证范围与现场验收

自动化测试覆盖协议编解码、通信模拟与部分界面逻辑。实际设备、安装流程及长时间运行需要按使用环境单独验证。最终接入真实 PLC、仪表或变频器前，应确认通信参数、接线和允许写入的寄存器范围。完整操作与统计说明见[双角色连续读写验证](双角色连续读写验证.md)。
